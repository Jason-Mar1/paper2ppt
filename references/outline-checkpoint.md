# Deck Outline Checkpoint Template

Use this template for Step 1 of HTML PPT / reveal.js / visual paper deck requests. Keep the response short and easy for the user to approve.

## Response pattern

Start with one sentence:

> I will first lock the story and visual style, then generate the HTML deck after your confirmation.

Then provide:

### Proposed deck outline

1. **Title + one-line takeaway** — <main message>
2. **Motivation / problem** — <main message>
3. **Key insight** — <main message>
4. **Method overview** — <main message>
5. **Core modules / mechanism** — <main message>
6. **Results + evidence** — <main message>
7. **Final takeaway / limitation** — <main message>

Use 5 slides for a short spotlight, 6-7 slides for a richer conference-style talk, and more only when the user explicitly asks.

### Visual plan

- Figure for motivation: <figure/page/table, or placeholder if unavailable>
- Framework figure: <figure/page, or redrawn conceptual diagram>
- Module figure: <figure/page, if useful>
- Results figure/table: <compact table or chart from paper numbers>

### Recommended style

- **Palette:** blue-white academic
- **Language:** English-only, unless the user requested another language
- **Fonts:** Times New Roman for academic text; Comic Sans MS only for handwritten-style tags/callouts
- **Density:** concise, 3-5 bullets per slide
- **Figures:** use actual paper figures when available; redraw only if clarity improves

### Confirmation question

Ask exactly one direct question, for example:

> Shall I generate this version directly, or would you like to change the style, slide count, language, or figure usage first?

## Direct-generation exception

If the user says "directly generate", "no need to ask", "make it now", or similar, skip this checkpoint and generate the HTML deck immediately using the recommended style defaults.
